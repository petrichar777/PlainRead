## 三、安卓端：需要手动安装

以下步骤**必须由本机所有者操作**（涉及 GUI 安装程序与授权确认），无法自动完成。

### 3.1 安装 Android Studio

下载安装后首次启动会引导安装 SDK。也可只装 Command-line Tools，但 Android Studio 更省事。

### 3.2 通过 SDK Manager 安装组件

| 组件 | 建议版本 | 说明 |
|---|---|---|
| Android SDK Platform | **35** | 对应 `targetSdk = 35` |
| Android SDK Build-Tools | 最新 | |
| **NDK (Side by side)** | **27.2.x（钉死一个具体版本）** | ★ 不同 NDK 版本的链接行为不一致，团队与 CI 必须统一 |
| Android SDK Platform-Tools | 最新 | 提供 `adb` |
| Android SDK Command-line Tools | 最新 | 提供 `sdkmanager` |
| Android Emulator + 系统镜像 | API 35 / `x86_64` | 仅在用模拟器时需要 |

### 3.3 配置环境变量

```bash
export ANDROID_HOME="$LOCALAPPDATA/Android/Sdk"
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/27.2.<具体版本号>"
export PATH="$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin"
```

> Windows 上建议写入**系统环境变量**，而不是只写在某个 shell 配置里——否则从 IDE 或 Tauri CLI 启动时可能读不到。

### 3.4 添加 Rust 交叉编译目标

```bash
rustup target add aarch64-linux-android x86_64-linux-android
```

| target | Android ABI | 用途 |
|---|---|---|
| `aarch64-linux-android` | `arm64-v8a` | 现代真机（**必装**） |
| `x86_64-linux-android` | `x86_64` | 模拟器（开发期必装） |
| `armv7-linux-androideabi` | `armeabi-v7a` | 老 32 位设备（上架前再加） |

### 3.5 不需要装的东西（避免浪费时间）

| 组件 | 为什么不需要 |
|---|---|
| `cargo-ndk` | Tauri 2 的 Android 构建链会自行配置 NDK 工具链，无需手动管理 |
| `gradle`（独立安装） | Tauri 生成的工程自带 Gradle Wrapper（`gradlew`） |
| `cargo-apk` | 已被 Tauri CLI 取代 |
| `cargo install tauri-cli` | 改用 npm 安装 `@tauri-apps/cli` 更快（有预编译二进制，省掉数分钟编译） |

## 四、两种推进顺序

| 方案 | 说明 | 优劣 |
|---|---|---|
| **A. 桌面优先（推荐）** | 立即开始 M0 的桌面部分（工程骨架 + IPC 链路打通），安卓环境在方便时安装，装好后立刻补 `android init` 与空壳 APK | M0 的核心目标是**验证 IPC 契约链路**，这与平台无关。桌面先跑通能更早拿到反馈 |
| **B. 环境优先** | 先装好 Android 环境，再开始 M0，两端一起打穿 | 一次做完，不用切换上下文；但开始时间取决于安装耗时 |

> **无论选哪个，M0 的验收标准不降低**——桌面与安卓两端都跑通才算完成。

## 六、M0 实测发现的坑（务必记录）

### 6.1 首次编译极慢

| 项目 | 实测 |
|---|---|
| `reader-core`（6 个依赖） | **约 6 分钟** |
| `src-tauri`（完整 Tauri 依赖树，约 400 个 crate） | **约 27 分钟**（首次） |

这不是异常，是本机编译吞吐偏低（可能是磁盘或杀毒软件扫描）。**属一次性成本**，增量编译会快很多。
但要把它算进心理预期：改一行 Rust 代码触发重编译时，首次等待会比较久。

### 6.2 `indexmap` 探测失败导致 Tauri 编译中断

**症状**

```
error[E0107]: struct takes 3 generic arguments but 2 generic arguments were supplied
  --> schemars-0.8.22/src/lib.rs:12:32
12 | pub type Map<K, V> = indexmap::IndexMap<K, V>;
   note: struct defined here, with 3 generic parameters: `K`, `V`, `S`
  --> indexmap-1.9.3/src/map.rs:76:12
```

出错点在 `tauri-build → schemars 0.8.22`，**不是我们的代码**。

**根因**

`indexmap 1.9.3` 的 `[features]` 里**没有 `default`**，因此 `std` 默认关闭。它在这种情况下的 build.rs 会走真实探测分支：

```rust
match std::env::var_os("CARGO_FEATURE_STD") {
    Some(_) => autocfg::emit("has_std"),
    None    => autocfg::new().emit_sysroot_crate("std"),  // ← 会 spawn rustc 探测
}
```

探测失败（受限构建环境 / CI 沙箱 / 子进程受限）时 `has_std` 不会被 emit，于是
`map.rs` 里的 `IndexMap<K, V, S = RandomState>` 退化为三泛型版本 `IndexMap<K, V, S>`，
`schemars 0.8.22` 的 `Map<K, V>` 别名立刻编译失败。

**修复**（已写入 `src-tauri/Cargo.toml`）

```toml
# 显式启用 std，让 indexmap 走 emit("has_std") 分支，绕开运行时探测
indexmap = { version = "1.9", features = ["std"] }
```

**为什么这个修复是值得保留的（而不是一次性 hack）**

它把"能不能编译通过"从一个**环境依赖的不确定问题**，变成了**确定性问题**。
代价只是多一条不直接使用的依赖。收益是构建在本地、CI、别的机器上表现一致。

> 教训：这类"某个 crate 的 build.rs 会 spawn 子进程做探测"的依赖，
> 在受限构建环境里都可能突然失效。以后遇到类似症状（本地能编、CI 不能编，
> 或反之），优先怀疑 build script 的探测逻辑。
