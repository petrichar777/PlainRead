01 — DIRECTION

这次动的不是配色，是造型语言

参考项目最值钱的不是它用了什么颜色，而是它有一套自洽的比喻：档案。编号、索引线、套准标记、格网、等轴测书架——所有细节都在说「这是一间藏书档案室」。v1 的问题不是不好看，而是没有比喻：暖纸底 + 大圆角 + 卡片阴影，是通用阅读器长相，换个主色就能是任何 App。v2 把比喻补上。

① 奶白取代纸黄

底色从 #FBF8F0 提到 #F4F3EF：去黄、微冷、提亮。纸黄留给「阅读主题」，界面本身保持中性——桌面上长时间看，偏黄的界面会让白底内容显脏。

② 圆角从 16/24 收到 4/3

大圆角是 2019 年的语言，且不可逆地带来"玩具感"。档案系的圆角只做印刷品的轻微倒角：面板 4px、书封 3px、按钮 3px。质感靠 1px 描边和材质差，而不是靠"柔软"。

③ 加一层"元数据"

等宽小字承担编号、册数、章节、体积、日期（WJ-000118、CH.118 / 342）。它几乎不占视觉重量，但让界面从"卡片堆"变成"有编目的收藏"。

一个必须明确表态的冲突

v1 设计规范第 5 条写死了「双端同源：桌面端 = 大号手机端，不另造桌面语言」。本稿部分违背它：桌面端改用左侧栏骨架。理由是本阶段「桌面优先」，而 1440×900 下顶部栏 + 单列书墙会让 60% 的屏幕成为空白。折中方案：令牌、组件、图标、动效全部同源，只允许骨架断点不同——不是两套设计，是同一套设计的两种密度。此项需你点头（见 §11 D1）。

02 — COLOR

近乎单色，只留一处朱砂

整套界面只有三个色相：墨（文字与主操作）、奶白（承载面）、朱砂（当前位置）。彩色越少，朱砂的那一小条越有力——它是"你正读到这里"的唯一信号。朱砂面积硬性上限 5%，任一屏超出即视为走样。

03 — TYPE & GEOMETRY

两套字体，一条网格

界面用系统无衬线（锐利、零加载），元数据用等宽（对齐、机器感、档案感），正文用衬线（书感）。等宽层是 v2 新增的第三套字体角色——它不参与叙事，只负责"编目"。

字距是这套设计最大的杠杆

  • 大标题 −1.1px：中文大字在默认字距下会"散"，收紧后立刻有印刷味
  • 等宽小字 +1.05px：全大写拉丁 + 宽字距 = 档案标签的通用语言
  • 正文 0：中文正文绝不加字距，行高 1.9–1.95 承担呼吸
  • 字重只用 400 / 500 / 600 / 700 / 800 五档，不用 300（细体在 125% 缩放下会糊）

几何：4pt 网格 + 3px 倒角

  • 间距只用 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64，桌面大区块用 40 / 56
  • 圆角：标签 2px、书封/按钮 3px、面板 4px、对话框 6px。不使用 8px 以上
  • 描边统一 1px（不用 0.5px——125% 缩放下会消失成灰边）
  • 套准标记：7px L 形、0.7px 线，只在输入框聚焦、封面悬停、空状态框出现

SIGNATURE · REGISTRATION MARKS

搜索书名或作者

四角 L 形套准线是整套设计里唯一的"装饰"，也是最省成本的身份标记。规则：只在"被聚焦/被选中"的矩形上出现，静止态永不出现。它替代了 v1 的 ring 高亮（外发光），不会在小尺寸下糊成一团。

04 — COMPONENTS

组件：方、薄、有边

所有组件遵循三条：方（3–4px 倒角）、薄（高度 34/40，无内阴影）、有边（默认带 1px 描边，不靠背景色区分）。图标一律 Lucide 线性 2px，禁止 emoji（沿用 v1 硬性规定）。

06 — READER / DESKTOP

阅读页：正文 620px 是硬上限

v1 在 1440 宽的窗口里让正文跑满视口，一行能排 70–80 字——中文长行会导致换行丢行，是阅读体验最致命的细节。v2 把正文列宽锁在 620px（约 31 字/行），两侧留白交给"舞台"。桌面把目录做成常驻右栏（可 Ctrl+B 收起），手机仍是抽屉。

CHAPTER 007 · 第一卷 白马出凉州

夜宿听雪楼

风从长街尽头卷过来，带着雪粒和铁锈的味道。他把手拢进袖子里，慢慢往前走。

街两旁的灯一盏接一盏亮起来，像有人沿着屋檐数数。数到第七盏时，他停下来，抬头看了一眼招牌。招牌上的字已经褪成灰白，只有最末一笔还留着当年的金漆。

“还开着？”他问。

没人回答。门槛上积着薄薄一层雪，雪面平整，没有脚印。他伸手推门，门轴发出一声很长的呻吟。

屋里比外面更暗。柜台后坐着一个老人，正在擦一只瓷碗。碗是空的，擦得很仔细，一圈一圈，像在磨一面镜子。

“要住店？”

“要一间。”他把行囊放在脚边，“靠里那间。”

老人抬头看了他一眼，眼里没有惊讶，也没有盘问。这样的客人他见得多了，来的时候不说来路，走的时候不留姓名。

09 — INTERACTION

关键交互：只写会变的部分

v1 已定的手势与键盘矩阵全部保留（三分区点击、滑动跟手、Esc 层级回退）。这里只列因 v2 造型而必须调整的七处。

场景v1 行为v2 行为理由
书架悬停 无（触屏思维） 封面 上移 4px，180ms；书脊亮度 +8%，落影加深 桌面端鼠标是常态；"书被抽出一点"是最直觉的可点信号，比描边更物理
顶部栏呼出 点中央 40% 桌面：鼠标进入顶部 80px 区域即淡入（160ms）；点击中央仍有效 桌面用户不会想到"点正文中间"；hover 是零学习成本的入口。触屏路径保留
工具条自动隐藏 常驻直到再点中央 鼠标离开正文区 1.2s 且未操作工具条 → 淡出；拖动滑杆期间永不隐藏 桌面鼠标移动频繁，工具条常驻会一直压着正文；触屏端不变（点按切换）
多选 长按/右键 → 顶部栏变"已选 N 本" 勾选标记改为左上角 18×18 方框（2px 墨描边，选中填墨 + 白勾），封面压暗 12% 方形勾选块比圆形 ring 更符合档案语言，且不会在小封面上糊掉
目录当前章 朱砂左条 + primary-100 底 朱砂左条 + 淡朱砂底 + 编号变朱砂；展开时自动滚到视图上 1/3 处 三重信号保证在 320px 窄栏里也能一眼定位；上 1/3 让"下一章"同时可见
焦点环 2px 黛青外描边 2px 墨色外描边 + 2px offset；输入框额外点亮四角套准线 墨色焦点不会被误读成"选中状态"；套准线让聚焦这件事有品牌感
主题切换 整屏 300ms crossfade 保留 crossfade，但正文与 chrome 分开 40ms（chrome 先） 同时变会有一瞬"糊在一起"；错开 40ms 读起来像"灯先变、纸后变"

性能与兼容约束（继承 v1）

  • 立体书只用 transform / box-shadow / 静态渐变，不引入 filter 动画；一屏 18 本，DOM 节点 6×18 = 108，可接受
  • backdrop-filter 只允许出现在浮层（顶栏、底栏、Toast），书墙与正文禁用——这是 v1 就定的护栏
  • 正文列宽用 max-width:620px，分页 stride 仍按视口宽计算，锚点算法不受影响
  • 等宽字体走系统栈（Cascadia/Consolas），不新增字体文件
  • vite target 仍为 chrome90：color-mix() 不可用，色值一律写死十六进制
