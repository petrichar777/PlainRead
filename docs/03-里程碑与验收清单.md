### 0.2 旧清单的四个问题（为什么必须重排，而不是打几个勾了事）

| 问题 | 现象 | 后果 |
|---|---|---|
| ① **状态脱节** | 旧清单写「M2 待走查、M3 未开始」，而实际 P3（阅读页全壳）、P4（细节）、P5（文档）都已交付 | 进度看板失真，"还剩多少"无法回答 |
| ② **UI v2 不可见** | 六个批次横跨书架/阅读/目录/设置四屏，在旧清单里被拆碎塞进 M1/M2/M3 的旧条目 | 一整块工作没有归属，验收清单（06 §8 共 20 项）无处挂靠 |
| ③ **条目被决策作废** | 「字距调节」在 v2 变为「段距 + 字体」；「平板双栏」被 D4 否决；「沉浸=全屏」被重定义；「书签」缺契约 | 勾不掉的死条目混在活条目里，等于噪声 |
| ④ **未完成项散落三处** | M1 有 3 项性能实测、M2 有 8 项人工走查、06 §8 有 20 项视觉/无障碍验收 | 三次走查、三套口径，最终没人签字 |

### 0.3 重排的三条原则

1. **里程碑 ID 不重编号**，只插入 `M2.5`。
   ADR-006、`docs/README.md`、06 施工单都在引用 `M0–M5`（尤其「M4 = 安卓、M5 = 桌面打磨」是不可误解的锚点）。
   重编号会让 5 处以上引用失效、历史记录断裂——收益为零，代价是永久性的。
2. **任务按「可验收的闭环」组织，不按「代码层」组织。**
   旧清单按 `infra/encoding.rs`、`lib/anchor.ts` 这种文件粒度列条目，对跟踪进度没有意义。
   新清单每条都回答「用户能看到什么变了」。
3. **未完成项必须收敛到一个闸门。**
   实现状态归各里程碑；**人工签收统一在 M5 的 UAT 执行**（§7.4），每行引用来源条目号。
   一次走查、一套口径、一个签字日。

### 6.2.1 落地记录（2026-10-18，全部带实测）

**M3-1 书签**——契约按 ADR-007 的"只增不改"落地：

| 层 | 内容 |
|---|---|
| 仓储 | `repo.list_bookmarks(book_id)`（走 `bm_by_book` 前缀扫描，**不遍历全表**；孤儿倒排顺手自愈）+ `repo.remove_bookmark(id)`（实体+倒排一起删，**幂等**） |
| 命令 | `add_bookmark`（同位置幂等返回已有条；章节越界拒绝；摘录压平换行 + 按**字符**截断 60 字加省略号）/ `remove_bookmark` / `list_bookmarks`（按阅读位置排序） |
| 契约 | `gen:bindings` 后 `bindings.ts` 只增不改（`BookmarkDto` 的 `createdAt` 按惯例写了 `#[specta(type = Number)]`，i64 的坑见 §2.6） |
| UI | 顶栏书签钮（**toggle**：同章同偏移即视为已加，实心 + `aria-pressed`）；dock 书签列表钮；右栏书签面板（与目录共用 `.ui-side` 外壳，摘录两行截断，整行跳转 + 右侧独立删除键）；跳转 = `seekTo(章, 字符偏移)` 并收起侧栏 |

实测（无头 + 假 IPC，同会话）：加签 → `aria-pressed=true` + Toast「已加书签」；列表面板 2 条；点击跳回 1/4；删除 2→1；同一位置重复加签不产生重复。

**M3-2 边界反馈**——`goNext`/`goPrev` 在边界弹 Toast「已经是最后一页了 / 已经是第一页了」（复用 §4 的 Toast，3s 自动消失）。实测：第一章连按 8 次前进键，Toast 出现且页码钉在 1/4。

**M3-3 resize 重锚（R-01）**——修了**两个**叠加的根因：

1. **量测坐标系错误**（P5 已修，签收时记为 C7）：切面表量测必须把 track 位移归零。
2. **过渡动画污染量测**（本次新发现）：`.reader-track` 有 220ms 的 transform 过渡，归零位移会播放动画，此刻读 `Range` 坐标是**动画中间态**（实测列号 -3…1）→ 量测期间临时 `transition: none` 并强制 reflow。
3. **高度变化从不触发重排**（本次新发现）：观察器只盯宽度，而每页行数由高度决定——改窗口高度后页数按旧值算，正文被裁掉一截。现在宽、高都进观察器，任何一个变化都走「锚点登记 → 150ms 去抖 → 重建切面表 → 按锚点落页」。

实测（CDP 在同一会话内改视口）：1440×900 走到 4/4（页首字符偏移 1127）→ 改 900×760 → 4/5 且 **1127 仍在可视页内**（页起于 917）→ 改回 1440×900 → 3/4（1127 仍在页内）。页码随几何正确变化，位置不丢。
>
> **编号说明**：这里用 `M3-n` 而不是 `Dn`——`D1–D5` 已被 06 的五个设计决策占用（D4 = 不做对页双栏），
> 两套 D 编号并存会直接毁掉可追溯性。

- 原估 **M1 + M2 = 20 个业余人日**，实测约 **6 个日历天**（10-11 → 10-17）→ 代码类工作约 **×0.3**。
- 但 **M5 里 5 天不再打折**：性能实测、UAT 走查、安装包验证都是"必须真的跑出结果"的工作，
  不会因为写得快而变短；相反，它们最容易在最后暴露问题。
- 因此 M3 按"写代码 ×0.3"取 3 d，M5 按原估 8 d 压到 5 d（去掉已完成的平板断点部分），合计 8 d。
- ⚠️ 这是**单一样本校准**，误差大。真实节奏按 W1 结束时的实际消耗再校一次。
