## 排序原则

1. **安卓构建链在第 1 个里程碑就打通**（M0 末尾），而不是放到最后。
   > 安卓交叉编译 + Tauri 移动端工程生成，是唯一一个"环境问题可能连续几天定位不到"的环节。把它前置，最坏情况在项目第二天就暴露。**这一条在换用 Tauri 后依然成立**，因为 Rust 侧仍然要交叉编译。

2. **IPC 契约在 M0 就定下来**。
   > 这是 Tauri 方案下最容易返工的地方。契约一旦在 M1 之后大改，前端所有调用点都要跟着改。因此 M0 必须把命令骨架、错误类型、`tauri-specta` 自动生成链路全部打通。

3. **阅读器前端（M2）先于交互打磨（M3）**。
   > 分页与锚点算法是"好看且好用"的地基。地基歪了，翻页动画、书签定位、进度保存全都要返工。

### M0 手工验收步骤（自动化测试覆盖不到的部分）

下面这些**必须人工跑**，自动化测试只能覆盖到「契约链路」那一层。

#### A. 桌面端（约 3 分钟，无需额外环境）

```bash
cd code
npm run tauri dev
```

| 步骤 | 期望结果 | 不通过时先看什么 |
|---|---|---|
| 窗口自动弹出 | 标题「简阅 · PlainRead」，浅色卡片式界面 | 若编译报错 → 先跑 `cargo build -p plainread` 看具体错误 |
| 右上角状态胶囊 | 显示绿色「**IPC 链路正常**」 | 若红「链路异常」→ 说明 `src/ipc/bindings.ts` 未同步，跑 `npm run gen:bindings` |
| 「内核自检」卡片 | 示例书籍 / 原始编码 GBK / 章节数 12 章 / 默认字号 18px / 主题枚举 3 项 | 任一项显示不出 → 跨 crate 通路有问题 |
| 「IPC 往返测试」输入框保持默认，点「发送到 Rust」 | 出现绿色回传框，且末尾显示「**与前端一致 ✓**」 | 若「不一致 ✗」→ UTF-8 在 IPC 边界被破坏 |
| 改输入框为任意中文再点一次 | 字符数 / 字节数两栏都随之更新，且与 Rust 回传一致 | — |
| 关闭窗口 | 进程退出，无残留 | — |

> 这一步同时验证了「Tauri 窗口能起来」「WebView2 可用」「IPC 双向通」三件事。

#### B. 安卓端（需先完成 §3 的安卓环境安装）

```bash

# 1) 启动模拟器（Android Studio 的 Device Manager 里点 ▶，或命令行 emulator -avd <名字>）
adb devices          # 应当能看到 emulator-5554

# 2) 生成安卓工程（首次）
npm run tauri android init

# 3) 编译 + 安装 + 启动
npm run tauri android dev
```

| 验收项 | 期望结果 | 不通过时先看什么 |
|---|---|---|
| `android init` | 生成 `src-tauri/gen/android/` | 报找不到 SDK/NDK → `ANDROID_HOME` / `ANDROID_NDK_HOME` 未写入**系统**环境变量 |
| `android dev` | 模拟器上自动打开应用 | `emulator -accel-check` 看硬件加速；黑屏改 `hw.gpu.mode`（见 [04 §3.6](04-环境准备与M0前置检查.md)） |

| 打包 APK | `npm run tauri android build -- --apk` 产出 APK | 产物在 `src-tauri/gen/android/app/build/outputs/apk/` |
| 无白屏无闪退 | 反复冷启动 3 次都正常 | `adb logcat -d \| tail -100` 找 panic |

- [ ] 命令实现：`list_books` / `pick_and_import` / `import_paths` / `delete_book` / `rename_book`
- [ ] 事件实现：`import://progress` / `import://finished` / `import://duplicate`
- [ ] 前端书架页：列表 / 网格自适应 + 导入按钮 + 导入进度条 + 删除
- [ ] 测试语料 7 份入 `crates/reader-core/tests/assets/`

## M2 · 阅读器前端（最关键里程碑）

**目标**：一页纸上的字，位置、间距、断行全部达到"能看"的标准；字号变化不丢阅读位置。

> 这一节取代了 egui 方案中的「排版内核」里程碑。**排版质量由浏览器负责，我们负责把它配置对、把锚点算对。**

### 交付物

- [ ] 命令实现：`open_book` / `load_chapter`
- [ ] 阅读页骨架：章节文本渲染为段落结构（`<p>`）
- [ ] **CSS 多列分页**（`column-fill: auto`）+ 翻页位移控制
- [ ] **中文排版 CSS**：`line-break: strict` / `text-spacing-trim` / `text-autospace` / `text-indent: 2em`
- [ ] **进度锚点算法**：`TreeWalker` 建立字符偏移 ↔ DOM 映射，`charOffsetToPage` / `pageToCharOffset`
- [ ] 主题系统：白 / 纸黄 / 夜间 三套 CSS 变量
- [ ] 字号 / 行距 / 字距 / 页边距实时调节（CSS 变量驱动）
- [ ] 安全区适配：`env(safe-area-inset-*)`
- [ ] 上下章预取
- [ ] 进度保存（前端防抖 + 切后台立即保存）

### 验收标准

- [ ] **不变式（进度往返）**：`charOffsetToPage(pageToCharOffset(i)) === i` 对任意页成立，以 Vitest 测试覆盖
- [ ] **不变式（不丢字）**：`load_chapter` 返回的文本与 `content.txt` 中该章字节区间**逐字符一致**
- [ ] 拖动字号滑块后仍停在**原来那句话**（验证锚点是字符偏移而非页码）
- [ ] 改变窗口尺寸 / 旋转屏幕后进度不丢失
- [ ] 中文正文中，行首**不出现** `，。！？、；：）》」』】`，行尾**不出现** `（《「『【`（`line-break: strict` 生效）
- [ ] 生僻字与繁体字**不出现方框 / 豆腐块**（浏览器字体回退生效）
- [ ] 正文与状态栏 / 挖孔 / 底部手势条**无重叠遮挡**（安全区生效）
- [ ] 单章 5 万字的极端样本触发降级为滚动模式并给出提示（不卡死）
- [ ] 翻页切换耗时 < 50 ms（不含动画）
